# 阿米娅 Q 版 (amiya)

《明日方舟》阿米娅的 Q 版桌面精灵，六个状态帧，用 Google 的 Nano Banana
（`gemini-3-pro-image-preview`）生成，再确定性抠底对齐成图集。

**本地自用的同人精灵**：不用于发布、分发或任何商业用途，角色版权属于鹰角网络。

## 重新生成

通用脚本都在 `../lib/`，本目录只需要 `character.py`。第一个位置参数是角色目录
（缺省用当前目录）：

```sh
AMIYA=~/projects/dhs-moegirl/characters/amiya

# 1) 生成帧（必须用 agents3 的 venv，google-genai 装在那里）
cd ~/projects/agents3 && HTTPX_PROXY=socks5h://127.0.0.1:1234 \
  uv run python ../lib/generate.py $AMIYA

# 重画某一帧（仍然拿设定图当参考图，不会越跑越偏）
cd ~/projects/agents3 && HTTPX_PROXY=socks5h://127.0.0.1:1234 \
  uv run python ../lib/generate.py $AMIYA --only 03-working

# 只打印 prompt，不调接口
cd ~/projects/agents3 && uv run python ../lib/generate.py $AMIYA --dry-run

# 2) 抠底、对齐、拼图集（不走模型，可随意重跑）
cd ~/projects/agents3 && uv run python ../lib/cutout.py $AMIYA

# 3) 自检
cd ~/projects/agents3 && uv run python ../lib/check.py $AMIYA

# 4) 装进 dsh 的资源包仓库
bash ../lib/install.sh $AMIYA
```

**代理必须写 `socks5h://`**：`agents3/.env` 里存的是 `socks5://127.0.0.1:1234`，对
Google 一律返回 `000`（本地 DNS 解析失败）。判据是
`curl -x socks5h://127.0.0.1:1234 https://generativelanguage.googleapis.com/` 返回
**404 = 通**。

**生图很慢**：这一组每帧 130–220 秒（blue-blob 只要 22 秒），六帧约 16 分钟。一次
只跑一帧别批量超时，要跑多帧就放后台。

## 关于点名

Nano Banana 的安全过滤会拦掉 prompt 里受版权保护的角色名（返回空 content）。所以
`character.py` 里**只描述外形、不写角色名**——模型照样照着描述画出来。

## 设计取舍

| 决定 | 原因 |
|---|---|
| **不画她的剑** | 带剑等于每个状态都要重新摆一遍手，一致性成本高；132px 宽下也只是多一团黑色。要加就单开一个状态，别混进这五个。 |
| **道具放在头侧、贴着耳高** | 她是竖长身形。道具飘到画面顶部会顶高内容框，进而撑大每格画布、把所有帧的人物一起压小——blue-blob 就是这么被坑的。实测六帧总高全是 1178，约束生效了。 |
| **道具用亮黄加厚深蓝描边** | 与身体同色系的符号在深色主题下等于没有。这套配色两个主题都读得出来。 |
| **画布 384×704** | 见下。 |

### 画布是算出来的，不是抄的

内容实测 567×1179（长宽比 2.08，竖长）。要让尺度接近内置精灵（显示 132×229、人物
约 200px 高），反推缩放约 0.54，换算成画布高就是 700 上下；取 **32 的倍数**得 704——
32 的倍数保证显示高度 `132×704/384 = 242` 是整数，CSS 的 `background-size` 没有
取整误差。

结果：内容占宽 79%、占高 90%，显示尺寸 132×242，人物约 105×218px。

**不要照抄 blue-blob 的画布**（384×512，接近方形）：那是圆团子的形状。反过来，
蓝团子的 README 里也写了别照抄内置精灵的 9:16。画布得按内容实际形状算。

## 这一组特有的坑

### 眼白跨度当不了尺度锚点

原来自检用「同一高度上两帧的近白像素跨度」当尺度锚点（对 blue-blob 很准）。
对阿米娅不成立：她的眼睛是**蓝色虹膜加白色高光**，近白像素本来就少，还会混进
头发高光；`done` 那帧飘在头侧的**星星**甚至一度被当成了眼睛（量出 275）。

改了两处：

1. 眼白搜索**限定在身体这一连通域内**——道具是独立的一块，本来就该排除；
2. 尺度锚点换成**身体高度**。内容框不行（道具会撑大），身体宽度也不行（举手会撑宽），
   身体高度对站姿角色是稳的。实测六帧 633/633/633/633/622/633，离散度 1.8%
   （622 是 `done` 起跳、脚离地，容差给了 10%）。

眼白跨度降级成仅参考打印。

### 眼睛/高光让「眼白」这个词不适用

写检查脚本时别再假设角色有圆眼白。真正能发现「整体缩放偏小」的是**装箱报告**：
内容占画布的比例，以及换算成显示尺寸后人物有多少像素。统一缩放对六帧等比例，
所以各帧之间怎么比都看不出整体偏小。

## 文件

| 路径 | 说明 |
|---|---|
| `character.py` | **唯一事实来源**：角色句、风格句、道具规则、六帧姿态、画布规格 |
| `../lib/generate.py` | 调 Nano Banana 生成帧，支持 `--only` / `--dry-run` |
| `../lib/cutout.py` | 抠底、统一缩放、底边对齐、拼图集（不走模型） |
| `../lib/check.py` | 自检：底边、身体高度、道具对比度、装箱、图集规格 |
| `../lib/install.sh` | 装进 `~/.dsh/moegirl/packs/amiya/` 并设为当前使用 |
| `frames/0N-*.png` | 生成的原帧（洋红底，未处理） |
| `atlas.png` | 拼好的图集，六格 384×704 竖排 |
| `pack.json` | 资源包文档（画布、帧名、帧序列、动作、气泡） |
| `preview.png` | 浅色/深色主题下 1:1 显示尺寸对照 |

## 状态与动作

动作幅度比 blue-blob 收细：人形不适合挤压拉伸。

| 状态 | 帧 | 动作 | 表现 |
|---|---|---|---|
| idle | 0 | `breathe` + `blink` 序列 | 轻微起伏，每 4.8 秒眨一次眼 |
| working | 2 | `hop` | 小幅跳动，落地微压 |
| attention | 3 | `breathe` | 举手挥 + 黄色叹号 |
| approval | 5 | `await-decision` | 轻微侧倾 + 黄色问号 |
| done | 4 | `rejoice` | 双手上举起跳 + 星星 |

点击精灵触发 `reaction`（弹性缩放进 `fill: 'none'`），并浮出 💙。

要调时间轴不必重新生图——在 **设置 → 桌面精灵** 的编辑器里改，或手改 `pack.json`
后跑 `install.sh`。
